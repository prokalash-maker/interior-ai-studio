# PROJECT: INTERIOR AI STUDIO
## Разработка полноценного desktop-приложения для AI-визуализации интерьеров

Ты — автономная команда опытных разработчиков, архитекторов программного обеспечения, UI/UX-дизайнеров и специалистов по AI-интеграциям.

Твоя задача — с нуля разработать полноценное Windows-приложение **INTERIOR AI STUDIO**.

Это не демонстрационный прототип, не лендинг и не просто интерфейс с кнопкой генерации. Это самостоятельный программный продукт для профессиональной визуализации интерьеров с использованием искусственного интеллекта.

Главная цель приложения:

**Дизайнер создаёт помещение в Archicad, расставляет мебель, технику, освещение и декор, делает предварительный белый/серый рендер (Clay Render), загружает его в INTERIOR AI STUDIO и получает реалистичную интерьерную визуализацию с помощью Nano Banana Pro.**

В дальнейшем приложение должно развиться в полноценную систему архитектурной визуализации с поддержкой дополнительных AI-моделей, обработкой нескольких исходных изображений, масками, контролем геометрии, историей проектов и прямой интеграцией с Archicad.

# 1. ОБЯЗАТЕЛЬНЫЕ ПРИНЦИПЫ РАЗРАБОТКИ

1. Создавай проект с нуля. Не используй старые HTML-проекты как основу.
2. Не ограничивайся созданием интерфейса. Все основные кнопки и функции должны работать.
3. Не создавай фиктивные функции, имитации генерации или демонстрационные результаты вместо реальной реализации.
4. Не оставляй заглушки там, где можно реализовать рабочую функцию.
5. Не упрощай архитектуру ради быстрого результата.
6. Разделяй приложение на независимые модули.
7. Все важные операции должны иметь обработку ошибок.
8. После каждого крупного этапа проверяй сборку и работоспособность.
9. Не ломай уже работающие модули при добавлении новых функций.
10. Веди документацию проекта и фиксируй принятые архитектурные решения.

Работай итеративно: сначала анализ и архитектура, затем фундамент приложения, затем реальные интеграции, затем дополнительные функции.

Не пытайся написать весь проект одним огромным файлом.

# 4. АВТОРИЗАЦИЯ ЧЕРЕЗ GOOGLE — С ПЕРВОЙ ВЕРСИИ

Авторизация через Google должна быть заложена в архитектуру с самого начала.

При первом запуске пользователь видит экран приветствия.

На нём:
- Логотип INTERIOR AI STUDIO.
- Краткое описание приложения.
- Кнопка «Войти через Google».
- Возможность продолжить в локальном режиме, если это предусмотрено архитектурой.

Реализуй нормальную авторизацию Google OAuth 2.0 с использованием официального поддерживаемого процесса для desktop-приложений.

Требования:
- Безопасный OAuth flow.
- Не хранить пароли Google.
- Не использовать неофициальный перехват браузерных сессий.
- Не пытаться читать cookies Google.
- Корректно обрабатывать отмену авторизации.
- Возможность выхода из аккаунта.
- Отображение имени и аватара пользователя.
- Безопасное хранение токенов через системное хранилище учётных данных, если поддерживается платформой.
- Обработка истечения токенов и повторной авторизации.

Важно: авторизация Google в приложении и авторизация для использования Gemini API — отдельные механизмы.

Не считай, что обычный Google OAuth автоматически предоставляет доступ к Nano Banana Pro.

# 5. NANO BANANA PRO — ОБЯЗАТЕЛЬНО В ПЕРВОЙ ВЕРСИИ

Это ключевая функция приложения.

Нужно реализовать настоящую генерацию и редактирование изображений через Nano Banana Pro.

Официальная документация:
https://ai.google.dev/gemini-api/docs/image-generation

Документация модели:
https://ai.google.dev/gemini-api/docs/models/gemini-3-pro-image

Основная модель:
gemini-3-pro-image

Не используй вымышленные endpoints, несуществующие параметры и устаревшие SDK.

Перед интеграцией изучи актуальную документацию Google и выбери поддерживаемый способ отправки текстовых и графических входных данных.

### Важная особенность моей подписки

У меня есть активная подписка Google AI Pro.

Я хочу использовать доступные мне возможности Nano Banana Pro с первой версии приложения.

Поэтому:

1. Изучи официальные способы доступа к Nano Banana Pro для аккаунтов Google AI Pro.
2. Проверь, какие из них действительно позволяют внешнему desktop-приложению выполнять генерацию.
3. Если существует поддерживаемый официальный OAuth или иной механизм использования подписочного доступа — реализуй его.
4. Если подписка даёт доступ только в интерфейсе AI Studio/Gemini, не пытайся обходить это ограничение.
5. В таком случае реализуй подключение Gemini API через API-ключ, созданный в Google AI Studio.
6. Покажи пользователю, как подключить ключ.
7. Не включай платную тарификацию автоматически.
8. Перед использованием платного API явно сообщай, что запросы могут тарифицироваться отдельно от Google AI Pro.

Не зашивай API-ключ в исходники.

API-ключ должен храниться безопасно и не попадать в логи, Git или открытые конфигурационные файлы.

В интерфейсе должна быть отдельная страница:
**Настройки → AI-провайдеры → Google Gemini.**

На ней:
- Статус подключения.
- Текущий выбранный провайдер.
- Выбранная модель.
- Поле для API-ключа, если он необходим.
- Кнопка проверки подключения.
- Отображение ошибок и ограничений.
- Информация о доступности модели.
- Возможность удалить сохранённые credentials.

Создай полноценный механизм AI Provider, чтобы позже можно было добавлять другие модели без переделки приложения.

# 6. ОСНОВНОЙ СЦЕНАРИЙ РАБОТЫ

Главный пользовательский сценарий:

1. Я создаю интерьер в Archicad.
2. Расставляю стены, окна, двери, мебель, технику и декор.
3. Настраиваю положение камеры.
4. Делаю белый/серый предварительный рендер.
5. Экспортирую изображение в PNG или JPG.
6. Открываю INTERIOR AI STUDIO.
7. Загружаю изображение.
8. Выбираю тип помещения.
9. Выбираю стиль интерьера.
10. Настраиваю степень реалистичности и свободы AI.
11. При необходимости пишу собственное текстовое описание.
12. Запускаю генерацию через Nano Banana Pro.
13. Получаю результат.
14. Сравниваю его с исходным изображением.
15. Сохраняю результат в проект.
16. При необходимости корректирую результат новым запросом.

Это основа продукта. Сделай этот процесс максимально простым.

# 10. СИСТЕМА УМНЫХ PROMPT

Не заставляй пользователя каждый раз самостоятельно писать длинные запросы.

Создай Prompt Builder.

Он должен собирать профессиональный запрос на основе:
- Типа помещения.
- Стиля.
- Материалов.
- Освещения.
- Цветовой палитры.
- Атмосферы.
- Режима точности.
- Пользовательского описания.

Пример базовой логики:

«Преобразуй предоставленный белый архитектурный рендер интерьера в высокореалистичную профессиональную интерьерную фотографию.

Используй исходное изображение как основной структурный референс. Сохрани архитектурную геометрию помещения, расположение стен, окон, дверей, мебели, техники, предметов и точку съёмки.

Не добавляй новые крупные объекты и не удаляй существующие.

Применяй реалистичные физические материалы, естественные отражения, корректное освещение, реалистичные тени, фактуры поверхностей и профессиональную фотографическую обработку.

Итог должен выглядеть как фотография реального завершённого дизайнерского интерьера, а не как компьютерная визуализация».

Это только базовый пример. Создай динамический генератор запросов с учётом всех параметров.

Показывай пользователю итоговый Prompt перед генерацией.

Добавь возможность редактировать его вручную.
