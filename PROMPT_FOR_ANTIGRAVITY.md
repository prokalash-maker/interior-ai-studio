# Стартовый промт для Antigravity

Скопируй текст ниже в Antigravity при передаче проекта.

---

Ты продолжаешь разработку существующего проекта **AI Designer by V1PERCOREJZ** (историческое имя Interior AI Studio), Windows desktop app на Electron + React + TypeScript + Tailwind + ComfyUI. Текущая кодовая версия — **v2.6.0 Pro**. Новую сборку пока не упаковывать. Целевая машина пользователя: Windows 11, NVIDIA RTX 4050 Laptop с 6 ГБ VRAM; ComfyUI Portable расположен в `D:\AI\ComfyUI_windows_portable`, модели — в `D:\AI\models`.

## До любых изменений

Сначала последовательно изучи в корне проекта:

1. `HANDOVER_FOR_CODEX.md` — цели пользователя, требования к продукту, контекст железа и описание существующих функций.
2. `ANTIGRAVITY_HANDOFF.md` — подробный хронологический журнал изменений, сборок, проверок, открытых задач и известных ограничений. Используй его как историю изменений, а фактическое состояние проверяй в коде.
3. `DEVELOPMENT_ROADMAP_V2.5.md` — приоритеты дальнейшей разработки и критерии готовности.
4. `PROJECT_PLAN.md` — чек-лист реализации и отметки выполненных/открытых задач.
5. `COMFYUI_ARCHVIZ_SPEC.md` — техническая спецификация локальных графов, ControlNet Canny/Depth и генерации.
6. `TECHNICAL_ARCHITECTURE.md` и `RISKS_AND_MITIGATIONS.md` — архитектурные решения и риски. Некоторые детали могли устареть, поэтому не считай документы доказательством текущей реализации.
7. `README.md` и `package.json` — запуск приложения, команды сборки, зависимости и текущая версия.

После чтения проверь конкретную задачу в исходниках, а не полагайся только на описания: `src/` (соответствующие `views`, `services`, `components`, `i18n/locales/ru.ts`, `uk.ts`, `en.ts`, типы), а для системного IPC — `electron/main.cjs` и `electron/preload.cjs`. По необходимости изучи относящиеся к функции скрипты в `scripts/`, миграции и вызовы IPC. Не читай и не меняй несвязанные пользовательские данные.

## Текущее известное состояние

- Предыдущая v2.5.0 лежит в `release/`; текущая кодовая итерация v2.6.0 не упакована. Не удаляй старые релизы и не запускай `npm run dist`, пока новые функции и пользовательская приёмка не завершены.
- OAuth Desktop app config берётся из игнорируемого `electron/oauth.local.json` или build env `GOOGLE_OAUTH_CLIENT_ID` / `GOOGLE_OAUTH_CLIENT_SECRET` и копируется в `dist-electron/oauth.local.json` при build:electron. Обычный пользователь не должен создавать собственный Client ID. Фактический Google sign-in всё ещё требует ручной проверки в живом приложении; не публикуй и не выводи credentials.
- История рендеров обновлена до трёхпанельного History Workbench. Проверь визуально на живом Electron.
- Studio больше не симулирует проценты или этапы генерации по таймеру: до подключения настоящих backend events показывай только неопределённый статус и фактически прошедшее время.
- В Gemini Bridge есть проекты/ракурсы, master-дизайн, карта материалов и сохранение дизайн-вариантов. Ручная проверка multi-view и восстановления варианта после перезапуска ещё важна.
- Пользователь сообщил 11.11.2026, что локальный ComfyUI не достигает результата Nano Banana. Целевой ориентир качества — Nano Banana; приоритет разработки Bridge повышен, а ComfyUI остаётся альтернативой для бесплатной поштучно локальной/офлайн генерации и контроля геометрии, без обещания паритета.
- Gemini Web — пользовательский ручной/полуавтоматический bridge. Пользователь сам входит в аккаунт, отправляет запрос и скачивает результат. Не читать Google cookies, пароли или внутренние API; не автоматизировать обход ограничений сервиса. Учитывай реальные лимиты подписки/аккаунта: Bridge не даёт Pro-доступ всем пользователям.
- LoRA Studio собирает пары и экспортирует изображения и captions в набор для внешнего trainer. **Встроенного или установленного Kohya/sd-scripts и реального обучения в v2.6.0 нет. Не называй экспорт датасета тренировкой.**
- Пользователь ожидает в будущем настоящий локальный trainer; прежде чем его подключать, изолируй Python-зависимости от portable ComfyUI и проверяй доступную память 6 ГБ.
- Резервное копирование, импорт и очистка проектов уже реализованы, но нужен ручной round-trip тест на копии данных.
- Отсутствие ручной приёмки не означает, что надо останавливать независимую разработку; зафиксируй это как незакрытый критерий.

## Рабочий порядок для каждой задачи

1. Сформулируй кратко фактическое состояние, нужный результат и критерии приёмки; перед правками проверь существующие реализации и git diff.
2. Составь небольшой список исходников/документов, которые изменишь, и оцени риски для базы, пользовательских файлов, IPC, сборки и GPU.
3. Реализуй задачу согласованно с архитектурой. Сохраняй рабочие функции и обратную совместимость данных; миграции проверяй на копии старой базы.
4. Все новые/изменённые UI-строки добавляй во все три локали: русский, украинский и английский.
5. Различай сборочную проверку и ручную функциональную проверку. Не заявляй, что сценарий проверен в Electron/ComfyUI, если проверен только TypeScript или сборщик.
6. Зафиксируй каждое изменение для следующего разработчика в `ANTIGRAVITY_HANDOFF.md`: дата, причина, файлы/модули, поведение до/после, решения, команды и результаты проверок, ручная приёмка и оставшиеся ограничения. Обнови `PROJECT_PLAN.md` и `DEVELOPMENT_ROADMAP_V2.5.md`, когда меняется статус или приоритет.
7. Не удаляй файлы ради уборки, пока не проверил все ссылки/использования, не доказал ненужность и не убедился, что это не пользовательские данные/модели/ресурс. Береги содержимое `release/` и локальную базу.
8. По умолчанию не запускай `npm run dist`: упаковка — финальный шаг релиза после завершения функций и приёмки. Для изменённого кода проверь соответствующие build-команды; полный набор релиза `npm run build:renderer`, `npm run build:electron`, а `npm run dist` — только когда готовится новый выпуск.

## Фокус следующих задач

Ориентируйся на `DEVELOPMENT_ROADMAP_V2.5.md` (имя файла историческое, актуальная дата и статус внутри). Следующая продуктовая итерация должна в первую очередь улучшать Gemini Bridge и согласованность дизайна между ракурсами, потому что пользователь предпочитает качество Nano Banana результатам текущего локального ComfyUI. ComfyUI остаётся опциональным бесплатным локальным путём; не обещай паритет. Проверки History Workbench и Google OAuth также открыты. Пользователь подтвердил, что уже обучал LoRA, запретил устанавливать Kohya и планирует авторизацию Google своими действиями; не устанавливай trainer. Не преувеличивай возможности: обычная LoRA по целевым картинкам и captions учит визуальный стиль, но не парное преобразование clay→render и не точную фиксацию геометрии. ControlNet остаётся отдельным инструментом геометрии.
